# INFRA-XRAY — AI-Powered Infrastructure Evidence Verification Platform

INFRA-XRAY is a comprehensive, AI-powered platform designed to verify infrastructure projects, detect anomalies, and ensure transparency in public works. By analyzing multi-modal data—including PDF documents (Contracts, Bills of Quantities, Invoices, Inspection Reports), geographical metadata, and computer vision on site photos—the platform generates risk scores and actionable insights for infrastructure monitoring and fraud detection.

## Overview & Use Cases

INFRA-XRAY serves as a crucial tool for auditing and infrastructure monitoring.

**Key Use Cases:**
*   **Fraud Detection:** Automatically detects mismatches between claimed progress in documents (e.g., invoices) and verified quantities (e.g., via inspection reports or photos).
*   **Infrastructure Monitoring:** Tracks the progress of various infrastructure projects (roads, buildings, pipelines) across different states.
*   **Automated Auditing:** Replaces manual document cross-verification with an AI pipeline that extracts data from Contracts, BOQs, and Reports, then correlates it logically, financially, and geographically.
*   **Risk Scoring:** Computes an aggregated risk score based on red/yellow flags generated by the anomaly engine.

## Architecture

The project consists of three main components:
1.  **Frontend:** A modern web interface built with React, Vite, and Tailwind CSS. It provides a dashboard to view risk scores, a detailed project view with an evidence funnel, and geographic map views.
2.  **Backend:** A Node.js/Express API server that serves the processed data to the frontend and provides endpoints for fetching projects, flags, and AI-generated checklists.
3.  **Python Worker Pipeline:** The core AI processing unit that handles data generation, extraction (via LLM or regex), computer vision, geospatial checks, and cross-verification.

## Setup & Installation

### Prerequisites
*   Node.js and pnpm
*   Python 3.x
*   (Optional) Anthropic API Key for LLM-based extraction.

### 1. Environment Configuration
Create a `.env` file in the root of the project with the following:
```
ANTHROPIC_API_KEY=your_key_here    # Optional: enables LLM extraction, uses regex fallback otherwise
PORT=3001                          # Backend port
NODE_ENV=development
```

### 2. Generate Data
First, generate the synthetic documents and metadata used by the platform:
```bash
npm run generate-data
# Alternatively: cd scripts && node generate_synthetic_data.js
```

### 3. Run the Python Pipeline
Set up the python environment and run the processing pipeline:

```bash
cd python-worker
# set up venv
.venv/bin/python -m pip install -r requirements.txt

# 1. Data Quality Check
.venv/bin/python run_quality_check.py

# 2. Document Extraction
.venv/bin/python run_extraction.py

# 3. Verification Pipeline (run sequentially)
.venv/bin/python verification/run_verification.py
.venv/bin/python vision/run_vision_check.py
.venv/bin/python geospatial/run_geo_check.py
.venv/bin/python anomaly/run_anomaly_engine.py
```

### 4. Start the Application
Install dependencies and run both the frontend and backend concurrently from the root directory:
```bash
npm run setup
npm run dev &
```
*   **Frontend:** Runs on `http://localhost:5173` (or `5175`)
*   **Backend:** Runs on `http://localhost:3001`

## Data & Database Schema

Currently, INFRA-XRAY uses a file-based JSON schema stored in the `data/` directory to simulate a database. This allows for easy local development and demonstration.

If this were to be ported to a traditional database (like PostgreSQL or MongoDB), the schema would map as follows:

### 1. Projects Table (`data/projects.json`)
Acts as the central registry of infrastructure projects.
*   `id` (String): Primary Key (e.g., "proj_001")
*   `name` (String): Project Name
*   `state` (String): Location state
*   `type` (String): Type of project (road, building, bridge, etc.)
*   `status` (String): E.g., "In Progress"

### 2. Extracted Data & Evidence (`data/extracted/{project_id}.json`)
Stores the parsed information from various documents. This could be stored in multiple related tables or a JSONB column in Postgres.
*   `contract`: Sanctioned quantities, units, and boundaries.
*   `progress_report`: Claimed completion percentages.
*   `invoice`: Billed quantities and amounts.
*   `inspection_report`: Verified quantities and GPS tracks.
*   `evidence_records`: Array of individual pieces of evidence linking back to the raw source files.

### 3. Verification Flags & Anomaly Reports
Generated by the Python verification scripts (e.g., `{id}_cross_flags.json`, `{id}_report.json`).
*   `project_id` (Foreign Key)
*   `type` (String): Cross-verification, Vision, Geo, Anomaly.
*   `severity` (String): "Critical", "Warning", etc.
*   `description` (String): Detail of the anomaly.
*   `risk_score` (Integer): Aggregated score for the project.

## Usage

1.  **Dashboard:** Navigate to `http://localhost:5173` to view the list of all projects and their risk scores.
2.  **Project Details:** Click on a project (like `proj_002`) to see the evidence funnel. You can trace data from the initial contract down to the latest inspection report and see where mismatches occur.
3.  **Map View:** Provides a geospatial overview of where the project is taking place and where anomalies are located.

## Troubleshooting

*   **"No projects found":** Ensure you have run `npm run generate-data` to create the synthetic datasets.
*   **"No extracted data":** Ensure you have executed `python run_extraction.py` within the `python-worker` environment.
*   **Port conflicts:** If backend fails to start, check if port 3001 is in use: `kill $(lsof -t -i:3001)`.
*   **Python issues:** Ensure you have activated your virtual environment before running the python scripts.
