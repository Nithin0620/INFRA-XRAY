# INFRA-XRAY — AI-Powered Infrastructure Evidence Verification Platform

INFRA-XRAY is a comprehensive, AI-powered platform designed to verify infrastructure projects, detect anomalies, and ensure transparency in public works. By analyzing multi-modal data—including PDF documents (Contracts, Bills of Quantities, Invoices, Inspection Reports), geographical metadata, and computer vision on site photos—the platform generates risk scores and actionable insights for infrastructure monitoring and fraud detection.

## Overview & Use Cases

INFRA-XRAY replaces manual document cross-verification with an AI pipeline. It is built to bring transparency and efficiency to large-scale infrastructure monitoring.

**Key Use Cases:**
*   **Fraud & Overbilling Detection:** Automatically detects mismatches between claimed progress in documents (e.g., invoices) and verified quantities (e.g., via inspection reports or photos). For example, finding a project that billed for 9km of road but only completed 7.8km.
*   **Infrastructure Monitoring:** Tracks the progress of various infrastructure projects (roads, buildings, pipelines, bridges) across different states in real-time.
*   **Automated Auditing:** Extracts data from multi-modal sources (Contracts, BOQs, Reports) and correlates it logically, financially, and geographically.
*   **Risk Scoring:** Computes an aggregated risk score (0-100) based on red/yellow flags generated by an anomaly engine, allowing decision-makers to prioritize high-risk projects.

## Architecture Deep Dive

The system is designed with a decoupled architecture, separating the heavy AI processing from the web application.

1.  **Frontend (React/Vite/Tailwind):** A modern, responsive dashboard providing:
    *   **Project List:** Sortable overview with metrics and risk gauges.
    *   **Evidence Funnel:** Visualizes data points from the initial contract down to the latest inspection, making discrepancies obvious.
    *   **Map View:** Geospatial overview of project locations and anomalies.
    *   **AI Copilot:** Generates inspection checklists dynamically.
2.  **Backend (Node.js/Express):** A lightweight API server that acts as a bridge between the processed JSON data and the frontend. It serves endpoints for fetching projects, flags, and handling AI copilot requests (integrating with Anthropic Claude).
3.  **Python Worker Pipeline (The Engine):** This is where the heavy lifting happens. It's a sequence of scripts:
    *   **Phase 1: Quality Checker:** Validates files (PDFs, photos, metadata).
    *   **Phase 2: LLM/Regex Extractor:** Extracts structured JSON from raw documents (using Claude API or a fallback regex parser).
    *   **Phase 3: Verification Modules:** Runs rule-based checks, computer vision (damage detection), and geospatial logic.
    *   **Phase 4: Anomaly Engine:** Aggregates findings into a final risk score.

## Setup & Installation

### Prerequisites
*   Node.js (v18+) and `pnpm` (We recommend using `pnpm`)
*   Python 3.10+
*   (Optional) Anthropic API Key for LLM-based extraction (regex fallback available).

### 1. Environment Configuration
Create a `.env` file in the root of the project with the following:
```env
ANTHROPIC_API_KEY=your_key_here    # Optional: enables LLM extraction
PORT=3001                          # Backend port
NODE_ENV=development
```

### 2. Generate Initial Synthetic Data
First, generate the synthetic documents (PDFs) and metadata used by the platform:
```bash
pnpm run generate-data
# This runs scripts/generate_synthetic_data.js and populates the data/ folder.
```

### 3. Run the Python Verification Pipeline
Set up the python environment and run the processing pipeline to analyze the generated data:

```bash
cd python-worker
# install dependencies
pip install -r requirements.txt

# 1. Data Quality Check (Validates all files)
python run_quality_check.py

# 2. Document Extraction (Extracts structured JSON)
python run_extraction.py

# 3. Verification Pipeline (Run sequentially to cross-check data)
python verification/run_verification.py
python vision/run_vision_check.py
python geospatial/run_geo_check.py

# 4. Anomaly Engine (Computes final risk scores)
python anomaly/run_anomaly_engine.py
```

### 4. Start the Application
Install dependencies and run both the frontend and backend concurrently from the root directory:
```bash
# Install dependencies for both frontend and backend
pnpm run setup

# Start both servers in background
pnpm run dev &
```
*   **Frontend:** Runs on `http://localhost:5173` (or `http://localhost:5175`)
*   **Backend:** Runs on `http://localhost:3001`

## Data & Database Schema

Currently, INFRA-XRAY uses a file-based JSON schema stored in the `data/` directory. This acts as an embedded database for local development, enabling the pipeline to read and write without external DB dependencies.

If this were to be ported to a traditional database (like PostgreSQL or MongoDB), the schema would map as follows:

### 1. Projects Registry (`data/projects.json`)
The source of truth for all infrastructure projects.
*   `id` (String): Primary Key (e.g., "proj_001")
*   `name` (String): Project Name
*   `state` (String): Location state
*   `type` (String): Type of project (road, building, bridge, etc.)
*   `status` (String): Current status (e.g., "In Progress")

### 2. Extracted Evidence Data (`data/extracted/{project_id}.json`)
Stores the parsed and normalized information from various unstructured documents.
*   `contract`: Base constraints (sanctioned quantities, budget, GPS boundaries).
*   `progress_report`: Contractor's claimed completion status.
*   `invoice`: Billed quantities and financial amounts.
*   `inspection_report`: Third-party verified quantities and GPS tracks.
*   `evidence_records`: Array of individual pointers linking extracted facts back to the raw source files (PDF/JPG) for auditability.

### 3. Anomaly Flags & Risk Reports (`data/anomaly/*_flags.json`)
Generated by the Python verification scripts.
*   `project_id` (Foreign Key)
*   `type` (String): Category of anomaly (Cross-verification, Vision, Geo).
*   `severity` (String): "Critical", "Warning", etc.
*   `description` (String): Human-readable detail of the anomaly.
*   `risk_score` (Integer): Aggregated score for the project based on weighted flags.

## Usage & User Flow

1.  **Dashboard Overview:** Navigate to `http://localhost:5173`. You'll see a portfolio-level view of all projects. High-risk projects are highlighted.
2.  **Investigate a Flagged Project:** Click on a project with a high risk score (like `proj_002`).
3.  **Trace the Evidence:** Review the "Evidence Funnel". You can trace data from the initial contract (e.g., 10km road), down to the progress report (9km), the invoice (₹17.5Cr), and finally the inspection report (7.8km). The discrepancies generate automated flags.
4.  **AI Copilot Action:** Use the "Generate Inspection Checklist" to get AI-driven recommendations on what physical evidence to look for next, based on the specific anomalies found.
5.  **Geospatial Analysis:** Switch to the Map View to see physical boundaries and whether reported GPS coordinates fall within the expected project zone.

## Troubleshooting

*   **"No projects found":** Ensure you have run `pnpm run generate-data` to create the synthetic datasets.
*   **"No extracted data" on Frontend:** Ensure you have executed the full Python pipeline (`python run_extraction.py`, etc.) within the `python-worker` environment. The backend needs these JSON files to serve data.
*   **Port conflicts:** If the backend fails to start, check if port 3001 is in use: `kill $(lsof -t -i:3001)` (Linux/macOS).
